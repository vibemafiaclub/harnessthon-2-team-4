# 금지 패턴 (Forbidden Patterns)

> 출처: `design-system-enforcer/references/forbidden-patterns.md` — Figma 환경에 맞게 적응.
> **적용**: U막 제작-L / 제작-S가 준수, **A(FP1~FP6)** 가 노드 속성으로 판정, **C 체크리스트 #5**가 시각 판정.

## 대원칙

디자인 시스템을 **닫힌 어휘(closed vocabulary)**로 취급한다.

- `_system/brief.md` 토큰 표의 **T에 없는 값은 사용 금지**. 가장 가까운 중립 기본값으로 대체한다.
- 승인된 배리언트가 없으면 **컴포넌트의 중립 기본값**을 쓰고, `contracts/components.json`에 **누락 배리언트로 보고**한다.
- 🔴 **추론된 의미·장식 배리언트를 발명하지 않는다.** 없으면 만들지 말고 보고한다.

---

## 1. 장식 금지 (Decoration)

명시적으로 승인된 컴포넌트 계약이 없으면 아래를 추가하지 않는다.

| 금지 패턴 | Figma에서의 형태 |
|---|---|
| 유색 엣지/액센트 보더 | 한 변만 있는 유채색 stroke (개별 stroke weight로 구현한 좌/상단 강조선) |
| 상태색 카드 배경 | 카드 fill을 semantic 색상으로 지정 |
| 그라데이션 배경 | `GRADIENT_LINEAR` 등 헤더·프로그레스바·스켈레톤 shimmer 포함 |
| Glow / 유색 그림자 | `DROP_SHADOW` 의 color가 유채색 |
| 장식용 도형 레이어 | 의미 없는 원/블롭/라인 (CSS `::before`/`::after` 대응) |
| 플로팅 배지·리본 | 승인 없는 오버레이 배지 |
| 임의 아이콘 배경 | 탭·리스트 아이콘 뒤의 원/사각 배경 |
| 섹션 배경 장식 | 섹션 구분용 배경 fill/패턴 |
| 아바타 링·강조 보더 | 아바타 외곽 유색 링 |
| 미정의 전환·패럴랙스·커스텀 스크롤 인디케이터 | 모션 스펙(미도입)에 없는 모션 |
| 미정의 햅틱 | 모션 스펙(미도입)에 없는 햅틱 |

---

## 2. Semantic 색상 오용

| 금지 패턴 | 설명 |
|---|---|
| 실제 앱 상태가 아닌 곳에 Green/Red/Amber 사용 | semantic 색상은 **실제 상태**(성공·오류·경고·정보)에만 |
| Use/Avoid, Do/Don't, Good/Bad, Pros/Cons를 상태색 콘텐츠로 렌더 | 설명형 대비를 상태색으로 표현 금지 |
| 색상만으로 의미 전달 | 아이콘 또는 텍스트 레이블 병행 필수 (**HIG-A11Y**) |

🔴 **텍스트 의미를 색상에 매핑하지 않는다.** "긍정적인 문구니까 초록색"은 금지다.

---

## 3. 구조 금지 (Structural)

| 금지 패턴 | 설명 |
|---|---|
| 하드코딩된 색·반경·간격·그림자 값 | T 토큰/Variable 바인딩 없이 직접 입력 (**CS1·CS3·CS5**와 중복 판정 시 CS 우선) |
| 콘텐츠의 의미 범주에 따라 스타일이 바뀌는 카드 | 카드는 설명형 범주 전체에서 **시각적으로 불변** |
| 플랫폼이 이미 제공하는 컴포넌트의 커스텀 구현 | picker·sheet·toast·switch·pull-to-refresh는 네이티브 사용 (**HIG-LIST·HIG-MODAL**) |
| 상태가 정의되지 않은 인터랙티브 요소 | pressed/disabled/loading 배리언트 부재 |
| Safe Area·시스템 제스처 영역을 침범하는 요소 | (**HIG-LAYOUT**과 중복 판정 시 HIG 우선) |

---

## 4. 카드 불변 규칙

카드는 **설명형·정보형 범주 전체에서 스타일이 동일**하다. 의미를 나타내기 위해 카드 스타일을 바꾸지 않는다.

승인 없이 사용 금지: 액센트 보더, 유색 배경, 상태 modifier, 장식 레이어.

**리스트 행은 카드가 아니다.** 독립적으로 드래그·해제·선택 가능한 단위가 아니라면 컨테이너가 아니라 divider/간격으로 구분한다.

---

## 5. 누락 배리언트 처리 절차

승인된 배리언트가 없을 때:

1. 컴포넌트의 **중립 기본값**을 사용한다.
2. `contracts/components.json`의 `## 누락/미해결 항목`에 **누락 배리언트로 기록**한다.
3. ❌ 즉석에서 배리언트를 **발명하지 않는다**.
4. ❌ 유사한 다른 배리언트를 **의미상 재해석해서 쓰지 않는다**.

---

## 6. Light/Dark 편측 정의는 미정의

> 출처: `design-system-enforcer/references/design-tokens.md`

**한쪽 모드만 정의된 색상 토큰은 정의되지 않은 것으로 취급한다.**

U막 제작-L은 모든 색상 토큰에 Light/Dark 쌍을 정의해야 하며, 한쪽만 있으면 `_system/brief.md` 토큰 표의 `## 관찰 한계`에 기록하고 T에서 제외한다. A단계 HIG-COLOR(Dark Mode 지원) 검증이 이를 판정한다.

---

## A단계 검증 항목 (FP1~FP6)

| ID | 검증 | 심각도 |
|---|---|---|
| FP1 | 그라데이션 fill 사용 (`GRADIENT_*`) | Major |
| FP2 | 유채색 그림자 / glow | Major |
| FP3 | 한 변만 있는 유채색 stroke (액센트 보더) | Major |
| FP4 | 카드 fill에 semantic 색상 사용 | Major |
| FP5 | 장식 목적의 도형 레이어 (의미 없는 원/블롭/라인) | Minor |
| FP6 | 아이콘 뒤 임의 배경 도형 | Minor |

**중복 판정 규칙**: FP 위반이 CS(Closed-Set) 또는 HIG 위반과 중복되면 **CS/HIG를 우선**하고 중복 카운트하지 않는다.

**S가 비어 있으면**: FP1~FP6은 T/S와 무관하게 **패턴 자체를 금지**하므로 `미측정`이 아니라 정상 판정한다.

---

## 예외 절차

사용자가 **명시적으로 요청**한 예외만 허용한다.

1. A단계 보고의 `## 예외 사항`에 항목 ID·내용·근거를 기록한다.
2. 대원칙 축 충돌 우선순위를 적용한다 (`design-principle.md`).
3. 🔴 접근성 관련 금지 패턴(색상만으로 의미 전달)은 **예외 불가**.
