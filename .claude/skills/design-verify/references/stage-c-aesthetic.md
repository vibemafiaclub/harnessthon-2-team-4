# C단계 — 미적·게슈탈트 판단 (방법)

**반드시 `get_screenshot`으로 렌더한 이미지를 보고** 판단한다. 노드 속성 조회로 대체 불가 — 수치가 다 맞아도 눈에 이상하면 실패다.

> **기준값(합격선)은 여기 없다.** 각 항목이 이 프로젝트에서 "어디부터 실패인지"는 `projects/<슬러그>/criteria.md`의 "C단계 기준값"에 있다.

## 이 파일의 규칙 — 라벨 금지, 합격선 필수

각 항목은 **"무엇을 보면 그렇게 판단하는가"까지** 적혀야 한다. "위계가 좋아야 한다" 같은 라벨만 있으면 에이전트가 판단할 수 없고, 매번 다른 답이 나온다.

좋은 예 — 여백 리듬 항목의 서술:
> 카드 내부 패딩과 카드 사이 간격이 같으면 카드 경계가 뭉개져 보인다(게슈탈트 근접성). 카드 사이 간격이 내부 패딩보다 **눈에 띄게 커야** 카드 단위가 분리돼 보인다 → 프로젝트 합격선: 내부 16 vs 사이 12는 실패, 내부 16 vs 사이 24는 통과.

나쁜 예:
> 여백이 일관되어야 한다.

## 판단 항목

- [ ] **섹션 간 색온도·조명 일관성** — 같은 화면 안에서 배경/표면의 명도 단계가 임의로 튀지 않는가. 특히 상태색 여러 개를 나란히 놓았을 때 하나만 채도가 튀면 팔레트를 벗어난 것이다.
- [ ] **시각적 위계가 한눈에 읽히는가** — 스크린샷을 2초만 보고 "이 화면에서 지금 제일 중요한 정보/행동이 뭔지" 답할 수 있는가. 무엇이 1순위여야 하는지는 요구사항(PRD/`brief.md`)에서 가져온다.
- [ ] **여백 리듬의 체감 일관성** — 수치상 그리드를 지켜도 시각적으로 리듬이 느껴지는가. 위 근접성 원리 참고.
- [ ] **정보 밀도 번잡함 여부** — 한 단위(카드/행/섹션)에서 시선이 멈추는 지점이 몇 개인가. 상한은 B단계에서 고른 밀도 축과 정합해야 한다.
- [ ] **클리셰/AI슬롭 여부** — 과도한 그라디언트, 근거 없는 그림자 남발, 의미 없는 장식용 블롭/추상 도형, 이유 없는 이모지. 도메인 맥락상 추가로 금지할 클리셰는 `criteria.md`.
- [ ] **엣지케이스의 실제 완성도** — 빈 상태/로딩/에러가 텍스트 한 줄로 방치돼 있으면 실패. 무엇을 하면 채워지는지 안내 + 그 행동으로 이어지는 경로가 있어야 한다.

## 판단 절차

1. 전체 화면 스크린샷 1장 + 주요 섹션별 스크린샷을 각각 렌더.
2. 위 항목을 순서대로 이미지에 대고 확인. 통과/실패 + **무엇을 보고 그렇게 판단했는지 한 줄 근거.**
3. 실패 항목이 있으면 SKILL.md의 라우팅(국소결함/방향오류/반복실패)으로 원인을 분류.
