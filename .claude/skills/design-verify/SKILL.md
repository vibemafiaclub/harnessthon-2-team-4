# design-verify — A/C단계 검증

화면 제작 직후, 또는 수정 후 재검 요청 시 실행. A와 C는 성격이 다르니 순서 상관없이 둘 다 돌리되, **C는 반드시 스크린샷을 렌더한 뒤에** 판단한다 — 노드 속성 조회로 대체 불가.

**판정 기준값은 `projects/<슬러그>/criteria.md`에서 읽는다.** 이 스킬의 references는 방법(무엇을 어떻게 보는가)만 담는다. `criteria.md`가 없으면 검증을 시작하지 말고 먼저 만들라고 알린다 — 기준 없이 통과/실패를 선언하면 그때그때 다른 답이 나온다.

## A단계 — 구조적 사실 검증

체크 카테고리와 조회 원칙: [references/stage-a-structural.md](references/stage-a-structural.md). 기준값은 `criteria.md`의 "A단계 기준값". `get_metadata`/`use_figma` 조회만으로 예/아니오가 나온다. 스크린샷 불필요.

## C단계 — 미적·게슈탈트 판단

무엇을 보고 "어색하다/고급스럽다"를 판단하는지: [references/stage-c-aesthetic.md](references/stage-c-aesthetic.md). 각 항목의 합격선은 `criteria.md`의 "C단계 기준값". **반드시 `get_screenshot`으로 전체 화면 + 섹션별 스크린샷을 렌더한 뒤** 그 이미지를 보고 판단한다.

## 결과 보고 형식

각 체크 항목에 대해 통과/실패 + 근거를 짧게 남긴다. A단계 실패는 즉시 해당 속성만 고친다. C단계 실패는 아래 라우팅을 따른다.

### C단계 실패 → 원인 진단 → 라우팅

이건 `oss-design-harness` 스킬의 책임이지만 판단은 여기서 같이 내린다:

1. **국소적 결함**: 문제가 표면 속성 하나(간격 하나, 색 하나, 텍스트 한 줄)로 서술 가능하고, 그 속성만 고치면 다른 곳에 영향이 없다 → 그 속성만 고쳐 C 재검.
2. **방향 자체가 틀림**: 문제가 여러 화면/여러 속성에 걸쳐 반복되거나, 고치려면 레이아웃 구조 자체를 바꿔야 한다 → `oss-design-harness`의 B단계로 회귀 신호를 보낸다.
3. **반복 실패**: 같은 화면에 대해 이미 2회 이상 국소 수정을 시도했는데 같은 이유로 계속 탈락 → 0단계로 에스컬레이션 신호. `oss-design-harness`의 재시도 상한(3회)에 도달하면 자동 진행을 멈추고 사람에게 보고한다.

진단 결과는 반드시 "무엇을, 왜 그렇게 진단했는지" 한 문장으로 남긴다 — 다음 재검 때 같은 문제를 또 처음부터 진단하지 않도록.
