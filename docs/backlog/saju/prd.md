# [리허설 PRD] 사주 풀이 앱 — 하네스 확장 검증용

> **이 문서는 제품 PRD가 아니다.** 이전 프로젝트(invitation-scheduler)에서 쓴 하네스가 다른 도메인으로 옮겨 가는지 확인하는 fixture다. 요구·가정·비목표·열린 결정을 명시했고, 실제 제작 전에 사람이 확정·교체한다.
> **포맷 규약(invitation-scheduler PRD와 동일)**: 화면 개수·레이아웃·색·타이포는 적지 않는다. 무엇을 해결해야 하는지만 적는다.

## 1. 배경

자기 사주를 가볍게 확인하고 싶은 사용자가 출생 정보를 넣고 풀이를 읽는다. 정보를 넣는 과정에서 출생 시각을 모르는 경우가 흔하고, 음력·윤달 같은 달력 문제가 섞인다. 결과는 길고 용어가 낯설다.

## 2. 핵심 유저스토리

1. **사용자로서**, 생년월일·시각·달력 종류를 넣고 내가 넣은 값이 맞는지 확인한 뒤 풀이를 받고 싶다.
2. **사용자로서**, 출생 시각을 모를 때도 풀이를 받고, 시각 때문에 달라질 수 있는 부분이 어디인지 알고 싶다.
3. **사용자로서**, 입력을 고치면 이전 결과와 무엇이 달라졌는지(또는 이전 결과가 더 이상 유효하지 않다는 것을) 알고 싶다.

## 3. 사용자들의 상황

- 출생 시각을 정확히 모르는 사용자가 상당수다.
- 부모 세대 정보는 음력으로 기억되는 경우가 있고, 윤달 여부가 불확실하다.
- 풀이 텍스트는 길다. 한 화면에 다 들어가지 않는다.
- 풀이 요청이 실패(네트워크·서버)할 수 있다.

## 4. 기능 요구사항

1. **출생 정보 입력**: 생년월일, 출생 시각(모름 선택 가능), 달력 종류(양력/음력), 윤달 여부(음력일 때), 성별. 출생지는 이번 범위 밖.
2. **입력 확인**: 넣은 값을 한 번에 보여 주고 수정으로 돌아갈 수 있어야 한다.
3. **풀이 요청과 상태**: 요청 중 / 결과 준비 / 실패를 구분해서 보여 주고, 실패 시 재시도할 수 있어야 한다.
4. **결과 읽기**: 긴 결과를 섹션으로 나눠 읽을 수 있어야 하고, 출생 시각 미상일 때 영향받는 섹션이 표시돼야 한다.
5. **입력 수정 후 결과 처리**: 입력을 바꾸면 기존 결과가 무효라는 사실을 알 수 있어야 한다. (병기·비교는 열린 결정)

## 5. 조건

- 개인 정보를 저장하지 않는 것을 기본으로 한다(저장·로그인은 비목표).
- 결제·궁합·오늘의 운세·공유는 이번 범위 밖.
- 단정적 표현·조언성 문구의 허용 범위는 열린 결정이다 — 화면에 자리(placeholder)만 두고 문구는 확정하지 않는다.

## 6. 열린 결정 (하네스가 `차단`으로 표시해야 하는 항목)

| 결정 이름 | 필요한 시점 |
|---|---|
| 출생 시각 모름 허용 방식(전체 미상 / 시간대 범위 선택) | 0단계 |
| 입력 수정 시 기존 결과 표시 정책 | 0단계 |
| 음력·윤달 수집 여부 | 0단계 |
| 풀이 표현 수준·용어 설명 방식 | C 판단기준 승격 전 |
| 대상 Figma 파일·시각 기준(토큰) | build 전 |
