# Screen Map — 화면 인벤토리 · 까다로운 경우 커버리지 · 더미 데이터

> `AGENTS.md` §5·`team-playbook.md` §4가 참조하는 문서. 제작단계(worker)와 검증(reviewer)이 같은 표를 본다.
> PRD 원문: `docs/prd.md`. 토큰·상태 어휘: `design/_system/brief.md`.

## 1. 정보 구조 (IA)

```
[커플 앱 · 하단 탭 4개]
 ├ 홈            S01
 ├ 지인          S02 ── 지인 등록/편집 S03
 ├ 모임          S10 ── 모임 편성 S04 ── 일정 후보 제시 S05
 │                    └ 모임 상세: 회신 수합 S06 → 확정 대기 S07 → 확정 공유 S08
 └ 일정          S09 (신랑+신부 통합 월 캘린더, 겹침 표시)

[게스트 웹 링크 · 탭 없음]
 └ 게스트 응답   S11 (여러 커플 요청을 한 화면에서 응답)
```

핵심 흐름(평가 기준 1): **S02 지인 풀 → S04 모임 편성 → S05 후보 제시 → S06 회신 수합 → S07/S08 확정 → S09 조망**.
각 화면의 CTA가 다음 화면을 가리키도록 만든다(끊김 없음). Figma에서는 `03 Screens` 페이지에 이 순서대로 좌→우 배치.

## 5. Figma 데이터 규약 (평가 기준 3 — "에이전트가 읽을 수 있는 데이터")

- 페이지: `00 README`(데이터 모델·상태 어휘·읽는 법) / `01 Foundations` / `02 Components` / `03 Screens`
- 모든 색은 변수 `color/*`에 바인딩, 간격은 `space/*`, 모서리는 `radius/*`. 하드코딩 HEX 금지(예외: `_system/brief.md` exceptions).
- 모든 텍스트는 텍스트 스타일 9종 중 하나를 참조.
- 화면은 전부 오토레이아웃. 절대 배치는 캘린더 점·배지 오버레이 등 최소.
- 컴포넌트 배리언트 속성은 상태 어휘와 동일한 값(`status=waiting|ready|confirmed|done`, `side=groom|bride|both`).
- 각 화면 프레임 `description`에 "목적 / 진입 / 다음 화면 / 다루는 까다로운 경우"를 적는다.
