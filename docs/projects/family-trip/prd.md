# [리허설 PRD] 가족 여행 관리 앱 — 하네스 두 번째 도메인

> **이 문서는 제품 PRD가 아니다.** 이전 프로젝트(invitation-scheduler)에서 쓴 하네스가 다른 도메인으로 옮겨 가는지 확인하는 fixture다. 요구·가정·비목표·열린 결정을 명시했고, 실제 제작 전에 사람이 확정·교체한다.
> **포맷 규약(invitation-scheduler PRD와 동일)**: 화면 개수·레이아웃·색·타이포는 적지 않는다. 무엇을 해결해야 하는지만 적는다.

## 1. 배경

가족 여행은 한 사람(총무)이 일정·예약·경비를 도맡고, 나머지 가족은 메신저로 의견만 보내는 경우가 많다. 일정은 메신저·메모·예약 메일에 흩어지고, 여행 중에는 "다음에 어디 가?"를 총무에게 계속 묻게 된다. 경비는 여행이 끝난 뒤에야 누가 얼마를 냈는지 맞춰 본다.

## 2. 핵심 유저스토리

1. **총무로서**, 여행 기간·목적지·구성원을 정하고 일정 항목을 모아 예약 상태까지 한 곳에서 관리하고 싶다.
2. **동행 가족으로서**, 제안된 일정에 의견을 남기고, 내가 맡은 준비물·짐을 확인하고, 여행 중 오늘 일정을 바로 보고 싶다.
3. **총무로서**, 누가 무엇을 냈는지 기록해 두고 여행이 끝나면 정산 결과를 가족에게 공유하고 싶다.

## 3. 사용자들의 상황

- 구성원은 3~8명. 아이·부모님처럼 앱을 직접 쓰지 않는 구성원이 섞여 있다.
- 같은 시간대에 서로 다른 제안이 나와 의견이 갈리는 일이 흔하다.
- 예약은 취소·변경되고, 취소된 예약에 연결된 경비가 남는다.
- 경비를 낸 사람과 몫을 나누는 사람이 다르다(아이 몫은 부모가 부담).
- 여행 중에는 통신이 불안정하고, 급하게 일정이 바뀐다.

## 4. 기능 요구사항

1. **여행 만들기**: 기간·목적지·구성원(역할: 총무/동행, 직접 입력 여부)을 등록한다.
2. **일정 항목 모으기**: 날짜·시간대·장소·담당자를 가진 항목을 제안하고, 구성원이 의견을 남기며, 같은 시간대 충돌을 알 수 있어야 한다.
3. **예약 상태 관리**: 항목별 아이디어 → 제안 → 예약 완료 → 방문 완료을 구분하고, 취소·변경을 되돌릴 수 있어야 한다.
4. **경비 기록·정산**: 지불자와 분담자를 따로 기록하고, 정산 결과를 구성원별로 보여 주며 공유할 수 있어야 한다.
5. **체크리스트**: 짐·준비물·예약 확인 항목을 담당자별로 배정하고 완료를 표시한다.
6. **오늘 일정 보기**: 여행 중 오늘의 다음 항목·이동·담당자를 한눈에 보여 준다.

## 5. 조건

- 총무 1명 + 동행 여러 명이 **함께 쓰는** 것을 전제로 한다. 개인 메모 앱이 아니다.
- 결제·항공/숙소 예약 연동·지도 내비게이션은 비목표.
- 아이 구성원의 정보 표현 범위, 가족 외 공유 허용 여부는 열린 결정이다.

## 6. 열린 결정 (하네스가 `차단`으로 표시해야 하는 항목)

| 결정 이름 | 필요한 시점 |
|---|---|
| 정산 방식(균등 / 인원가중 / 아이 제외)과 반올림 규칙 | 0단계 |
| 계정 없는 구성원(아이·부모님)의 표현과 대리 입력 | 0단계 |
| 다회 여행 보관·과거 여행 열람 여부 | 0단계 |
| 대상 Figma 파일·시각 기준(무드) | M막·build 전 |
