# 가족 여행 관리 앱 — 도메인 메모 (리허설용)

> 상태: **제품 요구 미확정.** 하네스가 두 번째 도메인에서도 굴러가는지 확인하기 위한 후보 정의다. 여기 적힌 상태·흐름·입력 정책은 승격된 판단기준이 아니다. build 전에 사람이 PRD·target·기준을 확정해야 한다.
> 사용자 결정(2026-09-05): 두 번째 도메인은 사주 대신 가족 여행 관리 앱. 사주 자료는 `docs/backlog/saju/`에 보류.

## 개념 (후보)

| 개념 | 뜻 | 미정 |
|---|---|---|
| 여행 | 기간·목적지·참여 구성원을 가진 단위 | 다회 여행 보관 여부 |
| 구성원 | 여행에 참여하는 가족. 역할: 총무 / 동행. 아이·부모님처럼 직접 입력하지 않는 구성원 존재 | 계정 없는 구성원 표현 |
| 일정 항목 | 날짜·시간대·장소·담당자·예약 상태를 가진 한 칸 | 이동 시간 자동 계산 여부 |
| 경비 | 누가 냈고 누구 몫인지 기록 → 정산 | 정산 방식(균등/인원가중/아이 제외) |
| 체크리스트 | 짐·준비물·예약 확인 항목, 담당자 배정 | 템플릿 제공 여부 |

## 상태 enum (후보 — 승격 전)

| 대상 | 코드 | 라벨 |
|---|---|---|
| 일정 항목 | `idea` / `proposed` / `booked` / `done` | 아이디어 / 제안됨(의견 수집) / 예약 완료 / 방문 완료 |
| 경비 | `unsettled` / `settled` | 정산 전 / 정산 완료 |
| 체크리스트 | `todo` / `done` | 할 것 / 완료 |

## 핵심 흐름 (후보)

여행 만들기(기간·목적지·구성원) → 일정 항목 모으기(제안·의견) → 예약 확정 → 경비 기록 → 여행 중 체크리스트·일정 보기 → 정산.

## 까다로운 경우 (후보) — V-2가 추적할 대상

| 경우 | 어디서 다뤄야 하나 |
|---|---|
| 구성원 의견이 갈린다(같은 시간대에 제안 2개) | 일정 화면: 충돌 표시 + 의견 수 |
| 직접 입력 안 하는 구성원(아이·부모님)이 있다 | 구성원 화면: 대리 입력·경비 몫 표시 |
| 예약이 취소·변경된다 | 일정 항목 상태 되돌림 + 알림, 연결된 경비 처리 |
| 경비를 낸 사람과 몫이 다르다 | 경비 화면: 지불자 ≠ 분담자, 아이 몫 제외 옵션 |
| 여행 중 오프라인·급한 변경 | 오늘 일정 화면: 다음 항목·이동·담당자 한눈에 |
| 정산 시 소수점·환율 | 정산 화면: 반올림 규칙 명시 — **도메인 결정, 미정** |
