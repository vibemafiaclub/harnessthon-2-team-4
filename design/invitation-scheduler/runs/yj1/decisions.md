# Decisions — 청첩장모임 스케줄러

## 식별된 독립 축

- **축 1**: 홈 화면의 1차 프레임 (캘린더형 vs 상태별 리스트형)
- **축 2**: 모임 카드 정보 밀도 (고밀도 펼침형 vs 저밀도 압축형)
- **축 3**: 지인 다중 소속 표현 방식 (텍스트 태그 나열 vs 색상 도트+텍스트 병기)

(축을 나누지 않고 화면 전체를 통째로 비교하면, 무엇 때문에 선택했는지 뒤섞여 판단 근거가 안 남는다.)

## 축별 후보·비교·선택

### 축 1: 홈 화면의 1차 프레임

| 후보 | 설명 | 비교 근거 | 선택 여부 |
|---|---|---|---|
| 캘린더형 | 월간 캘린더에 모임을 날짜별 점으로 표시, 날짜 탭하면 상세 | UX관점: 날짜가 이미 정해진 모임을 "언제인지" 확인하기는 빠름. 개발호환성: FullCalendar류 그리드는 컴포넌트 재사용이 애매(주차마다 다른 셀 개수). | |
| 상태별 리스트형 | 대기중/확정앞둠/확정됨/완료 4개 섹션으로 모임 카드 나열 | UX관점: PRD §3 핵심 문제("메신저 방이 늘어나 놓치기 시작")는 날짜가 아니라 상태 추적 실패 — 리스트가 직접 해결. 개발호환성: 카드 컴포넌트 하나 + 상태 변형만으로 전체 화면 구성 가능, 재사용률 높음. | ✅ |

**선택 이유**: PRD가 명시한 문제(§4-6 "진행 상태 구분")와 정확히 대응하고, 컴포넌트 재사용 관점에서도 A단계 기준(재사용률 ≥90%)을 만족시키기 쉽다. 캘린더는 삭제하지 않고 2차 탭("전체 일정 조망", PRD §4-5)으로 이동.

### 축 2: 모임 카드 정보 밀도

| 후보 | 설명 | 비교 근거 | 선택 여부 |
|---|---|---|---|
| 고밀도 펼침형 | 카드에 참석자 아바타 전원 + 회신 현황(N/M명 회신) + 날짜 후보 리스트까지 항상 노출 | UX관점: 한 번에 다 보여 탭 수는 최소화. 개발호환성: 카드 높이가 참석자 수에 따라 크게 가변적 — variant 폭발 위험. | |
| 저밀도 압축형 | 모임명 + 참석자 요약(아바타 3개+N) + 상태배지만, 탭하면 상세로 확장 | UX관점: 지인 40~100명, 주당 모임 2~3건 겹치는 성수기(PRD §3)에는 리스트가 길어져 스크롤 피로가 관건 — 압축이 유리. 개발호환성: 카드 높이 고정, variant는 상태 4종만. | ✅ |

**선택 이유**: 성수기 시나리오(PRD §3)를 기준으로 삼으면 리스트 길이가 병목이 된다. C단계 "정보 밀도 번잡함" 기준(카드당 시선 정지점 3개 이하)과도 정합.

### 축 3: 지인 다중 소속 표현 방식

| 후보 | 설명 | 비교 근거 | 선택 여부 |
|---|---|---|---|
| 텍스트 태그 나열 | "대학동기 · 직장동료 · 동네친구" 텍스트를 줄줄이 나열 | UX관점: 정확하지만 소속이 3개 이상이면 한 줄을 넘어가 리스트 아이템 높이가 들쭉날쭉. | |
| 색상 도트 + 텍스트 병기 | 그룹별 고정 색상 도트를 아바타 옆에 표시 + 대표 그룹명 1개만 텍스트로 병기, 나머지는 "+2" | UX관점: 리스트 아이템 높이 고정, 스캔 속도 빠름. 색맹 접근성 우려 → 텍스트 병기로 상쇄. | ✅ |

**선택 이유**: 리스트 아이템 높이를 고정해야 컴포넌트 재사용률(A단계 기준)을 지킬 수 있고, 텍스트 병기로 색상 단독 의존을 피해 접근성 하한을 만족.

## 남은 트레이드오프

- 저밀도 카드를 선택했기 때문에, 회신 현황("3/5명 회신")처럼 자주 확인하고 싶은 정보가 한 단계 더 들어가야 볼 수 있다 — 마감 임박 배지로 일부 상쇄했으나 완전한 해결은 아니다. C단계에서 "시각적 위계" 항목으로 재검증 필요.
- 초대받은 지인 전용 화면을 이번 스코프에서 제외한 것(brief.md 가정 로그)은 PRD 유저스토리 2번을 완전히 구현하지 못했다는 의미 — 다음 반복에서 0단계 재진입 대상.

## C단계 검증에서 확인된 사항 (2026-09-05 1차 제작 후)

- **여백 리듬(criteria.md 기준) — 실패 → 수정 완료**: 카드 내부 패딩 16 vs 카드 사이 간격이 처음엔 12로 만들어져 기준(내부16/사이12=실패)에 정확히 걸렸다. 카드 사이 간격을 24로 올려 재검 통과. 국소적 결함으로 분류, B단계 재논의 불필요했음.
- **정보 밀도(criteria.md 기준) — 확인된 긴장 관계, 미해결**: 저밀도 축 선택 시 카드당 3요소(모임명/참석자요약/상태배지)로 제한하기로 했으나, brief.md의 "마감기한은 1급 정보" 요구를 지키려고 회신현황+마감 행을 추가해 실제로는 4요소가 됐다. 두 요구가 서로 당긴다 — 지금은 마감 정보 쪽을 우선했다. 카드를 더 압축할지, 밀도 축 결정 자체를 재논의할지는 사람 판단 필요.
- **엣지케이스 완성도(criteria.md 기준) — 미구현**: "모임 없음" 빈 상태 화면을 이번 1차 제작에서 만들지 않았다. 안내문구+행동버튼 조합으로 추가 제작 필요 — 다음 반복 대상.
