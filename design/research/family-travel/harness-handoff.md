# 가족 여행 레퍼런스 — Harness 전달

상태: 조사·패턴 제안 완료. 사람 선택·기준 승격·M/W/I/U 잠금 없음. Figma 제작·검증 없음. 이번 루트는 `design/research/family-travel/`이다. 기존 프로젝트의 PRD·brief·토큰·target은 수정하지 않았다.

## 1. 현재 하네스의 4막에 연결

| 단계 | 이번 조사에서 읽을 것 | 사람에게 확인할 것 | 아직 하지 않을 것 |

| 0-R | references.json, evidence-review.md, reference-review.md | 요소별 채택·보류·제외 | 증거 검수를 취향 승인으로 해석 |
| M 무드 | gallery.html의 화면 영역 | 사진 비중·친근함·정보 밀도 반응, 유사 사례 되묻기 | 앱 브랜드색·폰트를 그대로 토큰화 |
| W 와이어프레임 | 아래 P01~P08와 흐름 후보 | 화면 순서·핵심 CTA·읽는 가족의 경로 | LOCK-M을 UX 승인으로 해석 |

이 자료는 다음 프로젝트의 입력 패키지다. 가족 여행 프로젝트를 실제로 시작할 때 프로젝트 설정·PRD·brief·system brief를 새로 만들고 본 패키지를 참조한다. 연구 도중 부부 일정 또는 사주 프로젝트의 승인값을 가져오지 않는다.

## 2. 추출 패턴 — 모두 proposal

### P01. 가족 관계·여행 참가·편집 권한 분리

- **근거**: REF-FW-01, REF-CZ-01, REF-WL-01. 보기/편집 구분은 [Wanderlog 공식 절차](https://help.wanderlog.com/hc/en-us/articles/4625495771163-Add-friends-to-plan-together), 예약 정보 범위는 [TripIt 공식 절차](https://help.tripit.com/en/support/solutions/articles/103000063367-trip-sharing-in-the-tripit-website).
- **문제**: 가족 명단과 실제 여행 참가자가 달라 일부 동행·비참가자의 권한이 섞임.
- **가설**: 이름·아바타·역할을 함께 보여주면 누가 가고 누가 수정하는지 구별하기 쉬울 수 있다.
- **적용 제안**: 가족 멤버와 여행 참가자 별도 관리. 초대에 ‘보기/함께 편집’ 설명. 계정 없는 자녀의 여행 참가 여부는 보호자가 기록하는 안 검토.
- **제외**: 가족이면 모든 문서·비용을 공유한다는 가정, 권한을 색만으로 표시.
- **필요 상태 후보**: 초대 대기·만료·권한 변경·참가 취소·계정 없는 동행자.
- **검증 질문**: 초대한 지원자가 수정할 수 있는지, 예약번호를 볼 수 있는지 사용자가 설명하는가?
- **노드 연결 예정**: `Member/Chip`, `Invite/RoleOption`, `Trip/Participants`. 이름은 제안이며 naming 원장 승인 전 확정 아님.

### P02. 공용·개인 준비물과 담당자 연결

- **근거**: REF-CZ-03의 묶음, [FamilyWall 담당자·준비물 소개](https://play.google.com/store/apps/details?id=com.familywall). 담당자 배정 동작은 직접 실행하지 않았다.
- **문제**: 누군가 했을 것이라고 생각해 준비가 빠지거나 중복됨.
- **가설**: 물건의 사용 대상과 담당자를 별도 표시하면 개인·공용 준비 책임을 구분할 수 있다.
- **적용 제안**: 항목·대상·담당·완료 상태를 한 행에 연결. ‘아직 담당 없음’은 이름 칸의 빈 공간으로 남기지 않는다.
- **제외**: 전체 목록이 완료돼 보이는데 실제로는 개인 필터만 완료된 표현.
- **필요 상태 후보**: 담당 없음·중복 항목·완료 취소·담당자 이탈·오프라인 수정 대기.
- **검증 질문**: 참가자가 빠진 뒤 공용 준비물이 누구에게 남는지 찾을 수 있는가?
- **노드 연결 예정**: `Packing/Item`, `Packing/ScopeFilter`, `Assignee/Picker`.

### P03. 여행 단계에 맞는 ‘오늘’ 요약

- **근거**: REF-CZ-02. 간결 보기 분리는 REF-WL-04와 [웹 기능 설명](https://help.wanderlog.com/hc/en-us/articles/13356092870427-Itinerary-compact-view); 모바일 동작은 별도 제안.
- **문제**: 정보를 확인하려는 가족이 계획 편집·장소 탐색 화면에서 다음 행동을 찾지 못함.
- **가설**: 여행 전에는 준비 마감, 여행 중에는 다음 일정과 예약 바로가기를 앞에 두면 읽기 과업을 지원할 수 있다.
- **적용 제안**: 현재 여행 단계 표시, 다음 일정·집합·남은 준비를 요약. 일정 전체와 편집으로 가는 경로도 유지.
- **제외**: 사용자가 모르는 사이 내비게이션 전체가 바뀌는 구성, 확인 홈을 대형 사진으로 채우기.
- **필요 상태 후보**: 출발 전·진행 중·종료·오늘 일정 없음·이동 중·마지막 업데이트 오래됨.
- **검증 질문**: 계획에 참여하지 않은 가족이 다음 집합 장소와 시간을 찾는가?
- **노드 연결 예정**: `Today/NextAction`, `Trip/Phase`, `Today/PreparationSummary`.

### P04. 일정별 대화와 현재 확정값 구분

- **근거**: REF-TT-02, REF-FW-01. 변경 요약·동의 상태는 새 설계 제안이다.
- **문제**: 댓글 제안과 실제 확정 시간이 달라 서로 다른 정보로 이동함.
- **가설**: 현재 일정값과 관련 대화가 연결되되 시각적으로 구분되면 혼동을 줄일 수 있다.
- **적용 제안**: 일정 헤더에 현재 시간·장소, 아래에 의견·첨부. 시간 변경 시 이전/현재와 변경자를 요약하는 안 검토.
- **제외**: 메시지 읽음을 일정 동의로 간주, 댓글 마지막 문장으로 일정 확정값 대체.
- **필요 상태 후보**: 의견만 있음·변경 제안·확정됨·취소·오래된 링크·전송 실패.
- **검증 질문**: 늦게 읽은 가족이 댓글 제안과 확정 시간을 구별하는가?
- **노드 연결 예정**: `Schedule/Header`, `Schedule/ChangeSummary`, `Comment/Composer`.

### P05. 장소와 이동 구간을 같은 일별 흐름에 배치

- **근거**: REF-WL-01/02. 휴식·부분 동행·합류는 우리 앱의 추가 제안이다.
- **문제**: 장소 목록만 보고 실제 이동과 체류에 필요한 시간을 놓침.
- **가설**: 장소 사이 이동을 독립 행으로 읽으면 하루 계획의 실현 가능성을 논의하기 쉬울 수 있다.
- **적용 제안**: 날짜 → 장소 → 이동 → 다음 장소. 이동 행에는 수단·예상시간·길찾기. 값이 없을 때 ‘미확인’을 표시. 모바일 지도는 전환·확장 형태 검토.
- **제외**: 지도·사진·비용·댓글을 모든 장소에 동시에 펼침, 추정 이동시간을 확정 소요시간으로 표현.
- **필요 상태 후보**: 미정 시간·이동값 없음·순서 변경·예약 시간 충돌·일부 동행·재합류.
- **검증 질문**: 일정을 늦췄을 때 뒤 예약과 이동이 가능한지 가족이 판단하는가?
- **노드 연결 예정**: `Itinerary/DaySelector`, `Place/Stop`, `Transit/Segment`, `Itinerary/MapToggle`.

### P06. 예약을 실제 이용자와 일정에 연결

- **근거**: REF-TI-01. 공개 목업을 구조 참고로만 사용한다.
- **문제**: 여러 가족의 티켓·숙소·교통 문서가 섞여 현장에서 찾기 어려움.
- **가설**: 유형·이용자·날짜·시간대 요약을 증빙과 연결하면 검색 부담을 줄일 수 있다.
- **적용 제안**: 예약 카드에서 상태와 실제 이용자, 현지 시간을 우선. 원본 증빙·주소·예약번호는 권한에 맞춰 상세로 연결.
- **제외**: PDF 파일명만 보여주기, 예약상태와 장소 선택 확정을 같은 상태로 사용.
- **필요 상태 후보**: 미등록·등록됨·변경·취소·첨부 실패·시간대 차이·보기 제한.
- **검증 질문**: 다른 숙소를 쓰는 가족과 자녀 예약을 헷갈리지 않고 찾는가?
- **노드 연결 예정**: `Reservation/Card`, `Reservation/Status`, `Attachment/Item`, `Time/LocalLabel`.

### P07. 오프라인 자료의 상태를 명시

- **근거**: REF-WL-03의 아이콘, 공식 다운로드 절차. 실제 오프라인 실행은 미검증.
- **문제**: 자료가 보이니 네트워크가 없어도 열릴 것이라고 생각함.
- **가설**: 자료 저장 상태·시각을 알리면 출발 전 준비 여부를 판단할 수 있다.
- **적용 제안**: 저장 범위·상태·마지막 갱신 시각. 저장되지 않은 파일과 최신 변경분을 구별.
- **제외**: 스크린샷의 아이콘을 오프라인 기능 성공 증거로 취급, 저장 실패를 숨김.
- **필요 상태 후보**: 저장 중·완료·실패·업데이트 필요·오프라인 변경 대기.
- **검증 질문**: 가족이 비행기 모드 전 어떤 정보가 저장됐는지 설명하는가? 실제 재열람 테스트는 구현 시 별도.
- **노드 연결 예정**: `Offline/Status`, `Offline/DownloadAction`.

### P08. 날짜·식사·휴식 의사결정 지원

- **근거**: REF-TT-01의 날짜 맥락, REF-FW-02의 식사 슬롯. 날짜 공유는 공식 설명만 확인.
- **문제**: 날짜 확정과 하루 활동 선택이 섞이고 모든 가족의 조건이 드러나지 않음.
- **가설**: 날짜 합의와 당일 일정 편성을 별도 과업으로 두면 결정 상태를 설명하기 쉬울 수 있다.
- **적용 제안**: 가능 날짜·미응답 → 날짜 확정. 하루 계획에는 식사·휴식 빈 슬롯을 검토. 자동 투표 집계는 새 설계 요구다.
- **제외**: 날짜 이미지 공유를 합의 완료로 간주, 식단·레시피 전체를 여행 기능에 편입.
- **필요 상태 후보**: 날짜 미정·동률·일부 응답·확정 후 참가 변경·식사 장소 미정.
- **검증 질문**: 누가 아직 답하지 않았는지, 날짜를 누가 확정했는지 알 수 있는가?
- **노드 연결 예정**: `Date/Proposal`, `Response/Status`, `Itinerary/MealSlot`.

## 3. W/I에서 사용할 연속 시나리오

‘조부모 2명·부부·자녀가 2박 3일 여행을 간다’는 테스트용 가상 조건이다. 실제 사용자 타깃·인원을 확정한 것이 아니다.

| 과제 | 확인할 동작 | 예상되는 갭 | 후보 검증 |
|---|---|---|---|
| 날짜 미정 여행을 만들고 가족 초대 | 응답하지 않은 사람과 여행 참가자 구별 | 초대 수락=참가 확정 혼동 | P01/P08, V-1/4 |
| 서로 다른 두 날짜 의견을 합의 | 미응답·동률·확정 주체 찾기 | 투표 표시만 있고 확정 흐름 없음 | P08, V-3/4 |
| 관광지 사이 이동·점심·휴식 배치 | 이동 없는 구간과 시간 여유 파악 | 모두 연속 방문 가능한 것처럼 보임 | P05/P08, C-2/4, V-5 |
| 가족 한 명의 항공편만 다르게 등록 | 실제 이용자와 시간대 찾기 | 예약을 가족 전체에 잘못 연결 | P06, V-5 |
| 공용 준비물 담당자가 불참 | 남은 항목 재배정 | 항목이 사라지거나 책임이 비어 있음 | P02, C-6, V-3/4 |
| 비로 첫 일정을 바꾸고 늦게 읽은 가족 확인 | 제안·현재 확정값·변경 요약 구별 | 옛 댓글의 시간을 따름 | P04/P05, C-2/6, V-5 |
| 네트워크 없이 숙소 정보를 찾기 | 저장 시각·첨부 준비 상태 확인 | 저장되지 않은 파일을 열 수 있다고 기대 | P07, C-6, V-3/4 |

## 4. 판단기준 후보 — 승격 전

| 후보 ID | 기준 후보 | 검증 입력 | 원장 매핑 |
|---|---|---|---|
| CR01 | 다음 집합 시간·장소가 보조 장식보다 먼저 읽히는가 | 오늘 화면 렌더와 사람의 찾기 과제 | C-2 |
| CR02 | 장소 정보와 이동 정보가 연결되면서 구분되는가 | 긴 하루 일정 렌더 | C-3/4 |
| CR03 | 담당 미정·변경·실패 상태에서 다음 행동이 읽히는가 | 예외 상태 렌더·CTA 연결 | C-6, V-3/4 |
| CR04 | 가족 친근함을 이름·맥락으로 표현하는가 | 무드 레퍼런스에 대한 실제 반응 필요 | C-5 후보, M 인터뷰 |
| CR05 | 참가자·날짜·예약 이용자가 화면 간 일치하는가 | 가상 데이터와 화면 인벤토리 | V-5 |

A에는 추정 픽셀값을 넘기지 않는다. U에서 토큰·스타일·배리언트를 정한 뒤 실제 노드를 검사한다. C 검수자에게는 확정된 행만, V에는 요구 계약과 실제 화면·상태·연결만 전달한다.
